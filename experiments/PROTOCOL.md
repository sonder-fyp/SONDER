# Bounded U1/U2 evaluation protocol (I2-A06)

**Task:** I2-A06, Iteration 2 package A2 (owner Ashher; independent reproduction Harris; run-loop interface check Ahmed).
**Why:** supervisor action summary (16 October 2026), item 2: commit seeded adaptive, fixed and random-selection experiments with equal question budgets; report wrong diagnoses, coverage, refusal and question counts together; define reference labels and data splits; separate tuning from evaluation; reproduce raw outputs independently.
**Status:** protocol version 1, written before any comparison was run. Changes after a held-out run must be recorded in the change log below and require a new held-out run.

Everything here uses **synthetic students under assumed parameters**. Results describe how the engine behaves on students generated by stated rules. They are not accuracy on real students, and model confidence is not measured accuracy.

## 1. Question

Under equal question budgets and the same stopping rules, how do adaptive expected-information-gain (EIG) selection, a fixed non-adaptive sequence and random eligible selection compare on wrong diagnoses, coverage, refusals and questions used, for students whose answers follow known generating rules on units U1 and U2?

## 2. Scope

| | |
| --- | --- |
| Units | U1 Rounding (20 items; MATH-1248, MATH-1379, MATH-1988, MATH-2392) and U2 Conversion (25 items; MATH-61, MATH-658, MATH-1715, MATH-1965, MATH-2039). Neither unit has twin items. |
| Content | `Maths_v2` as committed, identified by line-ending-independent SHA-256 of `bank/items.csv`, `topics.csv` and `sonder_pack/maths_v2_units.json` |
| Engine parameters | defaults (`Params()`), recorded in full in every manifest; question budget 8 |
| Remaining units | U3–U7 are outside this protocol; a dated plan for them is an I2-A10 deliverable |

## 3. Selection methods

All three methods use the same engine session: the same prior, Bayesian update, stopping rules R1–R5 (including R5's EIG floor, computed over the remaining eligible items for every method), the same eligibility rule (asked items and their twins are excluded) and the same maximum budget of 8. Only the choice of the next item differs. Each presented question records which method chose it and a truthful reason; a fixed or random choice is never described as an EIG choice.

| Method | Rule |
| --- | --- |
| **Adaptive** (production default) | The engine's `select_next`: highest EIG over eligible items, ties to the earliest item in pack order |
| **Fixed** | A non-adaptive order computed once per unit before any answer: items ranked by EIG at the prior, ties in pack order. Each question is the first item in that order that is still eligible. |
| **Random** | Uniform over the eligible items, from a selection generator seeded by (run seed, question position) on a stream separate from the student's answers |

Random **item selection** (a method) and a randomly **answering student** (a truth case) are different things and are reported separately.

## 4. Truth cases (reference labels)

A run's reference label is the generating rule's truth: a misconception ID, `NONE`, or *no named truth*.

| Case | How answers are generated | Reference label |
| --- | --- | --- |
| Intermittent holder of *m* | On an item that triggers *m*: with probability *apply rate* a uniformly chosen option linked to *m*; otherwise, and on every other item, a careful answer | *m* |
| No misconception | A careful answer on every item | `NONE` |
| Always-A | Option position A on every item | none named |
| Random answering | Each option with probability 1/4 | none named |
| Off-catalogue | A uniformly chosen wrong option that links no misconception when the item has one, otherwise a uniformly chosen wrong option | none named |
| Partial MATH-2039 holder (U2 only) | Applies MATH-2039 only where MATH-1965 predicts the same option; otherwise correct (KF-07) | MATH-2039 |

A *careful answer* is correct with probability 1 − *slip* and otherwise a uniformly chosen wrong option. A student's answer to an item depends only on (run seed, item), so the same student answers an item the same way under every selection method (common random numbers). The generation slip deliberately differs from the engine's assumed slip (0.10).

## 5. Tuning and held-out configurations

| | Tuning | Held-out |
| --- | --- | --- |
| Purpose | Inspect behaviour; compare candidate content/model/policy changes (I2-A04) | Report the comparison for an accepted version; never used to choose anything |
| Intermittent apply rates | 0.5, 0.7, 0.9 | 0.6, 0.8 |
| Careful-answer slip | 0.08 | 0.05 |
| Adverse cases | always-A, random answering, off-catalogue, partial MATH-2039 (U2) | random answering, off-catalogue |
| Seeds | 1000–1299 | 2000–2299 |

- **Runs per case:** 300 seeds for every (unit, truth case, method). Under adaptive and fixed selection, always-A and the partial holder are deterministic: they run one seed and are reported as single deterministic outcomes. Under random selection they run all 300 seeds. With 300 runs, a share near 50% has a 95% interval of about ±5.7 percentage points.
- **Seed ranges** never overlap each other or the adverse baseline (seeds below 1000).
- **Freeze rule.** The held-out configuration file is committed, and its SHA-256 recorded, before the held-out run. A held-out result is reported only with that hash, the content hashes, the parameters and the generating commit. Any parameter, threshold or content choice made after seeing held-out results invalidates them: record it in the change log and rerun on new seeds.

## 6. Raw outputs

`python -m experiments.evaluate --config experiments/configs/<name>.json` writes `experiments/results/<name>/`:

- `runs.csv`: one row per run, with unit, method, truth case and its parameters, reference label, seed, every asked item and the method that chose it, every answer, outcome, rule, reported label, tied set, R5 cause, questions used, and the final probability of the reported or leading hypothesis;
- `manifest.json`: generating commit and whether tracked files had changes, configuration hash, engine version, content hashes, every parameter, seed ranges, Python and NumPy versions;
- `metrics.csv`: every metric below, computed only from `runs.csv`.

Frozen tuning and held-out results are committed; exploratory runs are not.

## 7. Metrics (all computed from `runs.csv`, with denominators printed)

For **misconception-holder runs** (reference label a misconception), each run is exactly one of: *correct label*, *wrong label* (a different misconception), *missed* (`none_detected`), or *refused* (R3, R4, or R5 split by cause: budget, no items, EIG floor).

| Metric | Definition |
| --- | --- |
| Wrong-diagnosis rate | wrong labels ÷ (correct + wrong labels) |
| Coverage | (correct + wrong labels) ÷ holder runs |
| Correct coverage | correct labels ÷ holder runs |
| Missed rate | `none_detected` ÷ holder runs |
| Refusal rate, by rule and cause | refusals ÷ holder runs |
| NONE outcomes | for no-misconception runs: `none_detected`, false misconception label and refusal, each ÷ no-misconception runs |
| Adverse labelling | for cases without a named truth: runs given a misconception label ÷ runs, and the distribution of labels; these labels are never counted as correct or wrong |
| Questions used | mean (with a 95% percentile-bootstrap interval, 2,000 resamples, fixed resampling seed), median and full distribution |

Proportions carry Wilson 95% intervals. Every metric is reported per unit, per method, and per truth case, and pooled within a unit with its denominator. Posterior probabilities are reported as model output, never as accuracy, and no calibration score is computed against real students (none exist).

## 8. Comparisons and claims

- Methods are compared within a unit and truth case on the same seeds (paired). A difference is described with both intervals; no claim of superiority is made where the intervals overlap substantially.
- An improvement in one metric is reported together with its cost in the others (for example fewer wrong labels but more refusals).
- The proposal's targets (≤ 5% confident misdiagnosis with ≥ 70% coverage) are not evaluated here: they require a held-out set of real student responses.

## 9. Independent reproduction

Harris reruns the frozen held-out configuration from a clean checkout, confirms that `runs.csv` and `metrics.csv` match the committed files (or records any difference and its cause), recomputes at least one metric from the raw rows by hand or with his own script, and regenerates one figure. He records his own name, date, environment and result in `experiments/REPRODUCTION.md`.

## 10. Limitations

- Students follow simple, independent per-item rules; real students may combine misconceptions, change behaviour during a session or misread items.
- All engine parameters are assumed. A good result under students generated from similar assumptions is weak evidence.
- U1 and U2 are the units with the best separability; results do not transfer to U3–U7, which contain the inseparable pairs (KF-06) and sparse companions (KF-04).
- The content is a candidate bank pending external expert acceptance. Results must be rerun on the accepted version (I2-A05/A10).
